# Выбор базы для сессии

Порт сам по себе не говорит, какая база за ним стоит: runtime-клиент можно
перезапустить на другую базу, а конфигурация порта останется прежней. Поэтому
выбор всегда подтверждается ответом самой базы.

## Правила

1. **Единственный источник истины — реестр.** База берётся из
   `config/1c-projects.tsv`. Базы, которой нет в реестре, для skills не
   существует: сначала `add-1c-base`.
2. **Выбор подтверждается фактическим вызовом.** После выбора выполняется
   вызов, возвращающий идентификацию базы, и ответ сверяется с реестром. Без
   совпадения работа не начинается.
3. **Session lock.** Подтверждённая база фиксируется на сессию. Lock
   аннулируется при ошибке соединения, при повторном выборе, при перезапуске
   runtime-клиента и при смене порта. Аннулированный lock восстанавливается
   только повторным подтверждением по правилу 2, а не памятью о прошлом ответе.
4. **Обновление конфигурации.** Если не подтверждено, что база не была
   обновлена под другой релиз, работа прекращается.

## Production

База с `is_production = true` не выбирается неявно. Требуется отдельное
подтверждение пользователя в текущем диалоге, названное словами: какая база,
какой контур, зачем. Совпадения по имени, порту или «последней использованной»
недостаточно.

## Результат

Названы: `project_id`/`environment_id`, контур, порт, `application_kind`,
признак production, чем подтверждена идентификация. Это состояние session lock
для последующих skills.
