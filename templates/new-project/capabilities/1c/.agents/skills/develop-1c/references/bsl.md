# BSL: стиль, именование, структура модулей

## Форматирование

- Отступ — только TAB.
- Длина строки до 120 символов, если строку удаётся перенести осмысленно. Перенос,
  оставляющий на новой строке одну переменную, хуже длинной строки.
- Один оператор в строке. Однострочные конструкции со сложной логикой запрещены.
- Строки собираются через `СтрШаблон()`, а не конкатенацией `+`. Простое
  `Префикс + Суффикс` допустимо, когда читается лучше.
- Выравнивание `=` пробелами — только для групп присваиваний в локальные
  переменные. При установке свойств объекта через точку выравнивание не делается.
- Замечания линтера и BSL Language Server выполняются. Подавление — точечное,
  комментарием `//BSLLS:<правило>` с однострочным объяснением; подавление без
  объяснения запрещено.

## Метрики качества

| Метрика | Предел | Характер |
|---|---|---|
| Длина метода | 200 строк (тексты запросов не считаются) | жёсткий |
| Длина метода | больше 100 строк | повод декомпозировать |
| Вложенность управляющих конструкций | меньше 5 уровней | жёсткий |
| Когнитивная сложность | меньше 15 | повод для ревью |
| Число параметров | 5, шестым передаётся структура | жёсткий |

## Запрещённые конструкции

- Тернарный оператор `?(Условие, Значение1, Значение2)` — **в любом виде**,
  включая простой невложенный случай. Вместо него `Если ... Иначе` или
  вынесенная функция. Причина: логика должна быть видна в пошаговом отладчике и
  в ревью. Правило строже стандарта ИТС и принято осознанно.
- `Попытка ... Исключение` вокруг чтения и записи в базу — кроме явного,
  обоснованного управления транзакцией.
- `Сообщить()` для уведомления пользователя. Используются
  `ОбщегоНазначения.СообщитьПользователю` на сервере и
  `ОбщегоНазначенияКлиент.СообщитьПользователю` на клиенте.
- `ЗаписьЖурналаРегистрации()` без явного требования задачи — см.
  [`architecture.md`](architecture.md).
- `Выполнить()` и `Вычислить()` без крайней необходимости.
- Учётные данные в коде: пароли, токены, ключи API.
- Сравнение с `Истина` и `Ложь` — используется само булево выражение.
- Обратный порядок сравнения вида `Если 0 = Сумма`.

## Именование

- Имя отражает бизнес-смысл и роль. Суффикс типа допустим, только если снимает
  неоднозначность и не превращается в венгерскую нотацию.
- Венгерская нотация запрещена: `Контрагенты`, а не `МассивКонтрагентов`.
- Имена из глобального контекста платформы (`Документы`, `Справочники`,
  `Регистры`, `Метаданные`, `Константы`, `Пользователи`) не используются как
  локальные переменные — они дают коллизии.
- Префикс `Получить*` избыточен, когда результат очевиден из имени или функция
  возвращает коллекцию: `Контрагенты()` вместо `ПолучитьКонтрагентов()`.
  Допустим при прямом делегировании в платформенный вызов и в API, совместимом
  с БСП.
- Булевы переменные именуются положительно: `ПроверкаПройдена`, не
  `ПроверкаНеПройдена`.
- Магические числа запрещены — выносятся в именованные переменные или константы.
- Перечисления строковых значений — в алфавитном порядке.

## Условия и параметры

- Условие из трёх и более составляющих выносится в отдельный метод.
- Параметр не используется как дополнительный выход: всё, что метод возвращает,
  возвращается через результат.
- Набор дополнительных параметров передаётся структурой, собранной
  функцией-конструктором:

```bsl
Функция ПараметрыЗаполнения() Экспорт
	Параметры = Новый Структура;
	Параметры.Вставить("Дата");
	Параметры.Вставить("Валюта");
	Параметры.Вставить("ПересчитыватьСумму", Истина);
	Возврат Параметры;
КонецФункции
```

## Области модулей

Имена областей — русские, в стиле БСП. Английские `Public` / `Internal` /
`Private` не используются, кроме конфигураций, которые целиком ведутся в
английской локали единообразно.

Общий модуль:

```bsl
#Область ПрограммныйИнтерфейс
#КонецОбласти

#Область СлужебныйПрограммныйИнтерфейс
#КонецОбласти

#Область СлужебныеПроцедурыИФункции
#КонецОбласти
```

- `ПрограммныйИнтерфейс` — экспортные методы, доступные всей конфигурации.
- `СлужебныйПрограммныйИнтерфейс` — экспортные методы для собственных модулей
  проекта; сторонний код их не вызывает.
- `СлужебныеПроцедурыИФункции` — внутренние помощники, без `Экспорт`.

Области внутри процедур и функций запрещены. Псевдообласти комментариями —
тоже. Шаблоны для модулей объекта, менеджера и формы — в доставленном
`.agents/skills/1c-metadata-manage/docs/meta-manage.md` и в
[`forms.md`](forms.md).

## Комментарии

Предпочтителен самодокументирующийся код. Комментарий уместен, когда добавляет
то, чего в коде нет: мотивацию, неочевидный алгоритм, ограничение или побочный
эффект, маркер технического долга (`TODO №<задача>: ...`), обход особенности
платформы.

Запрещены комментарии, пересказывающие код, и баннеры с автором и историей
правок — это хранит git.

## Ревью после каждой правки

После правки кода выполняется внутреннее ревью, соразмерное объёму. Быстрая
правка — корректность и граничные случаи изменённого фрагмента, плюс блокировки
и транзакции, если рядом транзакционный код. Полный цикл — стиль, читаемость,
корректность, граничные случаи, безопасность, конкурентность, блокировки,
транзакции.

Перед открытием новой транзакции всегда проверяется, нет ли уже внешней
(например, транзакции записи объекта). Блокирующий дефект валидатора требует
чистого подтверждающего прогона на изменённом состоянии; незначительный
стилистический шум нового цикла ревью не запускает. Обязательные гейты — в
[`verification.md`](verification.md).

## Переиспользование

До написания нового кода проверяются экспортные методы общих модулей и модулей
менеджеров, шаблоны и механизмы БСП. Найденный шаблон берётся за основу:
адаптируются имена, отборы и размещение, а не переписывается решение целиком.
Порядок вызова инструментов поиска — в доставленном
`.agents/skills/mcp-1c-tools/docs/1c-templates-mcp.md`.
