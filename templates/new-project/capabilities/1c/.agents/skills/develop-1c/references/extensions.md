# Расширения

## Приоритет доработки

Режим поддержки берётся из колонки `support_mode` реестра баз, а не
предполагается. Конфигурация на поддержке дорабатывается расширением. Снятие с
поддержки — отдельное решение с последствиями для обновлений, а не побочный шаг
задачи.

Куда попадают новые объекты, задаёт `{NEW_OBJECTS_IN}` из `.dev.env`. При
значении `main_configuration` расширение только перехватывает события, новые
объекты идут в основную конфигурацию.

## Типы перехватчиков

| Директива | Что делает |
|---|---|
| `&Перед("ИмяМетода")` | код выполняется до оригинала |
| `&После("ИмяМетода")` | код выполняется после оригинала |
| `&ИзменениеИКонтроль("ИмяМетода")` | полная замена тела метода |

```bsl
&НаСервере
&Перед("ПриЗаписи")
Процедура Расш1_ПриЗаписи()
	// выполняется до оригинального ПриЗаписи
КонецПроцедуры
```

## `ПродолжитьВызов()`

- При `&Перед` вызывается автоматически. Вручную его писать не нужно.
- При `&После` оригинал уже отработал, и вызов не используется.
- При `&ИзменениеИКонтроль` вызов **обязателен**: без него оригинальный метод не
  выполнится вовсе. Это самая частая и самая тихая ошибка в расширениях —
  поведение пропадает без единой ошибки на экране.

## Маркеры изменений

Внутри `&ИзменениеИКонтроль` изменения размечаются обязательно:

| Маркер | Назначение |
|---|---|
| `#Вставка` / `#КонецВставки` | код, добавленный расширением |
| `#Удаление` / `#КонецУдаления` | оригинальный код, который заменён |

```bsl
&НаСервере
&ИзменениеИКонтроль("ОбработкаЗаполнения")
Процедура Расш1_ОбработкаЗаполнения(ДанныеЗаполнения, СтандартнаяОбработка)
	#Удаление
	// оригинальный код
	#КонецУдаления

	#Вставка
	// новый код
	#КонецВставки

	ПродолжитьВызов();
КонецПроцедуры
```

Маркеры сохраняют осмысленный diff при обновлении основной конфигурации, когда
объект приходится заимствовать заново. Без них обновление превращается в ручное
сравнение двух текстов.

## Заимствованные объекты

Заимствованный объект — не копия, а ссылка на объект основной конфигурации,
внесённая в область видимости расширения, чтобы к нему можно было прицепить
перехватчики и добавить своё. Определение остаётся в основной конфигурации, и
при её обновлении объект перечитывается, а расширение накладывается сверху.

Отсюда ограничения:

- Существующие реквизиты и табличные части заимствованного объекта удалить
  нельзя — они принадлежат основной конфигурации.
- Свои реквизиты и табличные части добавлять можно, с префиксом `{PREFIX}` из
  `.dev.env`.
- В модулях заимствованных объектов допустимы только перехватчики. Прямая правка
  тела оригинальной процедуры — нет.
- В формах заимствованных объектов можно добавлять элементы и нельзя удалять
  существующие.

## Антипаттерны

- Прямая правка модуля заимствованного объекта вместо перехватчика.
- Забытый `ПродолжитьВызов()` в `&ИзменениеИКонтроль`.
- Методы расширения без префикса: при следующем заимствовании они сталкиваются с
  именами основной конфигурации.

Работа с формами расширения — [`forms.md`](forms.md); особенности XML
метаданных при заимствовании — доставленный
