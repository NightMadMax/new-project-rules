# Архитектура, платформа, транзакции, логирование

## Размещение кода

- Бизнес-логика живёт в общих модулях, а не в модулях форм.
- Имена общих модулей следуют суффиксам БСП: без суффикса — серверный
  (`РаботаСЗаказами`); `Клиент` — клиентский; `КлиентСервер` — компилируется на
  обеих сторонах; `ВызовСервера` — серверный, вызываемый с клиента;
  `Глобальный` — глобальный клиентский; `ПовтИсп` — с повторным использованием
  возвращаемых значений; `Переопределяемый` — точки переопределения проекта.
- Модуль объекта на сервере обязан начинаться директивой
  `#Если Сервер Или ТолстыйКлиентОбычноеПриложение Или ВнешнееСоединение Тогда`.
- Подписка на событие предпочтительнее правки типового модуля.
- Куда попадают новые объекты метаданных, задаёт параметр `{NEW_OBJECTS_IN}` из
  `.dev.env`: `main_configuration` — в основную конфигурацию, расширение только
  перехватывает события; `extension` — новые объекты допустимы в расширении, а
  основная конфигурация без явного указания не меняется. По умолчанию —
  `main_configuration`.

## Приёмы

Составной результат возвращается структурой:

```bsl
Результат = Новый Структура;
Результат.Вставить("ПроверкаПройдена", ПроверкаПройдена);
Результат.Вставить("ТекстОшибки", ТекстОшибки);
Возврат Результат;
```

Ранний возврат снижает вложенность и предпочтителен вложенному `Иначе`:

```bsl
Если Отказ Тогда
	Возврат;
КонецЕсли;
```

## Клиент-серверное взаимодействие

- `&НаСервереБезКонтекста` обязателен для всех серверных методов, которые не
  обращаются к данным формы. `&НаСервере` допустим, только когда метод
  действительно читает или пишет реквизиты и элементы формы.
- Если методу нужно лишь значение реквизита формы, оно передаётся параметром.
- Модальные вызовы запрещены: `Вопрос()`, `Предупреждение()`, `ВвестиЧисло()`,
  `ВвестиСтроку()`, `ВвестиДату()`, `ВвестиЗначение()`, `ОткрытьЗначение()`.
  Способ зависит от `{PLATFORM_VERSION}` из `.dev.env`: до 8.3.18 —
  `ОписаниеОповещения`, с 8.3.18 — `Асинх` / `Ждать`. Внутри `Асинх` вызываются
  только асинхронные аналоги; смешивать нельзя. Диалоги на сервере запрещены.

## Безопасность

- `Выполнить()` и `Вычислить()` — без крайней необходимости запрещены.
- Учётные данные в коде запрещены. Секреты хранятся в подсистеме БСП или в
  защищённых от записи константах.
- RLS проектируется вместе с требованиями к доступу, а не добавляется потом.

## Обработка ошибок

- Локализация строк — `НСтр("ru = '...'")` вместе с
  `СтроковыеФункцииКлиентСервер.ПодставитьПараметрыВСтроку()`.
- Ошибки собираются в одну переменную через `Символы.ПС`.
- В журнал пишется `ПодробноеПредставлениеОшибки(ИнформацияОбОшибке())`, а не
  `КраткоеПредставлениеОшибки()`.
- Пустой обработчик исключения запрещён: либо запись в журнал, либо повторное
  возбуждение.

## Логирование

Запись в журнал регистрации — не побочный эффект отладки, а решение. Она
уместна для событий, которые кто-то будет искать: отказ интеграции, отклонённая
операция, результат фонового задания, изменение критичных данных. Обычный ход
выполнения в журнал не пишется.

- Имя события строится как `<Подсистема>.<Операция>.<Исход>` — по нему событие
  ищется, поэтому формат единый.
- Уровень выбирается по последствию, а не по эмоции: ошибка — операция не
  выполнена; предупреждение — выполнена с оговоркой; информация — факт для
  последующего разбора.
- В журнал не попадают секреты, персональные данные, тела запросов с учётными
  данными и содержимое, по которому их можно восстановить.

## Доступ к реквизитам по ссылке

Обращение через точку (`Контрагент.ИНН`) читает объект целиком. Правило проекта
строже стандарта ИТС: вне тривиального обработчика с одним вызовом это запрет.

| Метод | Назначение |
|---|---|
| `ОбщегоНазначения.ЗначениеРеквизитаОбъекта` | один реквизит одной ссылки |
| `ОбщегоНазначения.ЗначенияРеквизитовОбъекта` | несколько реквизитов одной ссылки |
| `ОбщегоНазначения.ЗначениеРеквизитаОбъектов` | один реквизит нескольких ссылок |
| `ОбщегоНазначения.ЗначенияРеквизитовОбъектов` | несколько реквизитов нескольких ссылок |

## Транзакции и блокировки

- Перед открытием транзакции проверяется, нет ли уже внешней. Запись объекта
  сама по себе выполняется в транзакции.
- Внутри транзакции запрещены: интерактивные действия, обращения к внешним
  системам, длительные операции и всё, что может не завершиться предсказуемо.
- Управляемые блокировки ставятся до чтения данных, которые затем изменяются, а
  не после.
- Порядок захвата блокировок в проекте единый — на нём держится отсутствие
  взаимоблокировок. Новый код следует уже принятому порядку; изменение порядка
  затрагивает всех и делается осознанно.
- Транзакция держится настолько коротко, насколько позволяет смысл операции.
  Массовая обработка разбивается на порции, а не выполняется одной транзакцией
  на всё.

## Совместимость

- COM-объекты (`Новый COMОбъект(...)`) запрещены, если задача не требует их
  явно. Для Excel используется табличный документ или БСП.
- Пути к файлам собираются платформенными функциями; обратный слэш не
  зашивается.
- Перед использованием метода платформы проверяется, что он существует в
  `{PLATFORM_VERSION}` из `.dev.env`.
- На сервере используется `ТекущаяДатаСеанса()`, а не `ТекущаяДата()`.

## Производительность

Каталог антипаттернов с примерами и уровнями критичности доставлен вместе с
upstream-скиллом; самые дорогие из них — запрос в цикле, обращение через точку
в цикле, коррелированный подзапрос, отсутствие `ПЕРВЫЕ N`, неиндексированная
временная таблица. Правила по запросам — в [`queries.md`](queries.md).
