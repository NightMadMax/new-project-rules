# Управляемые формы

## Гейт исполнения

Создание и структурное изменение `Form.xml` и разметки идёт через skill
`1c-metadata-manage`: он ведёт цепочку инструментов — кодировку и BOM, генерацию
UID, порядок дочерних объектов. Правка XML руками допустима только в узких
исключениях, описанных в самом skill, и об этом говорится вслух один раз.

Правка логики в `Form.Module.bsl` — обычная работа с BSL, под этот гейт она не
попадает.

Проверка XSD после любой правки XML обязательна: форма, которая разбирается в
редакторе, — ещё не форма, которая откроется в конфигураторе.

## Правки типовых форм

Изменения типовых форм выполняются программно, а не визуально. Элементы
создаются в обработчике `ПриСозданииНаСервере` либо через подписку или
расширение.

Элементы, добавленные в типовую форму, несут префикс `{PREFIX}` из `.dev.env`.
Внутри собственной новой формы, у которой объект уже с префиксом, повторять
префикс на каждом элементе не нужно.

## Модуль формы

- Пять обязательных областей — по шаблону модуля формы; они присутствуют, даже
  если пусты. См. [`bsl.md`](bsl.md).
- Бизнес-логика в модуле формы не живёт: её место — общие модули. В модуле формы
  остаётся то, что действительно про форму.
- `&НаСервереБезКонтекста` обязателен для серверных методов, не обращающихся к
  данным формы; значение реквизита передаётся параметром. Подробнее —
  [`architecture.md`](architecture.md).

## Зарезервированные имена

Локальные переменные в модуле формы **не** называются как стандартные свойства
элементов формы:

`ПараметрыВыбора`, `СвязиПараметровВыбора`, `СписокВыбора`, `ПараметрыОтбора`,
`ОтборСтрок`.

В серверном контексте модуля формы платформа может понять `ПараметрыВыбора = ...`
как попытку установить свойство элемента, а не присвоить локальную переменную, и
при несовпадении типа выдаёт ошибку несоответствия типов. Список составлен по
практике и может быть неполным: при подозрении на конфликт имя проверяется в
конфигураторе.

Имя даётся конкретное и контекстное:

```bsl
// плохо
ПараметрыВыбора = Новый Массив;

// хорошо
ПараметрыВыбораНоменклатуры = Новый Массив;
```

## Данные формы

- Преобразование между данными формы и объектами — `ДанныеФормыВЗначение()` и
  `ЗначениеВДанныеФормы()`.
- Реквизиты формы не равны реквизитам объекта: это представление, специфичное
  для формы.
- Доступность методов, реквизитов и элементов проверяется в контексте
  директивы, под которой пишется код.

## Асинхронность

Модальные вызовы запрещены. Способ зависит от версии платформы из `.dev.env`:
`ОписаниеОповещения` до 8.3.18 и `Асинх` / `Ждать` начиная с неё. Внутри `Асинх`
используются только асинхронные аналоги — смешение запрещено.

## Формы в расширениях

В форме заимствованного объекта можно добавлять элементы и нельзя удалять
существующие — см. [`extensions.md`](extensions.md).

## Порядок вызова инструментов

Последовательность анализа и генерации формы (поиск формы, разбор разметки,
получение схемы, проверка XML, компиляция) поставлена побайтно в
`.agents/skills/1c-metadata-manage/docs/form-manage.md` и `form-compile-dsl.md`.
Здесь она не дублируется: правила принадлежат этому файлу, порядок вызовов —
доставленному документу.
