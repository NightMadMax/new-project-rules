# Разворачивание и прогон тестов

## Исполнитель

Разворачивание выполняет `deploy-1c-source` скриптами пакетного режима из
`.agents/skills/1c-metadata-manage/tools/1c-db-ops/scripts/`. Запуск базы в
пакетном режиме для прогона — `db-run.ps1` оттуда же.

Исполнителя самих тестов capability не поставляет: он зависит от выбранного
уровня и установленных компонентов. Модульные тесты BSL требуют YAxUnit,
сценарные — своего инструмента; ни один из них не входит в поставку, и их
отсутствие даёт `SKIP` с названной причиной, а не молчаливый пропуск.

## Порядок

1. `deploy-1c-source` со всеми его предусловиями. Ни одно из них здесь не
   ослабляется: session lock, non-prod, подтверждённая резервная копия.
2. Определить доступный уровень проверок по `docs/quality/TEST_MODEL.md`.
   Уровни, для которых нет компонента, дают `SKIP` с названием причины.
3. Прогнать тесты выбранного уровня.
4. Отчёт: база, контур, ветка, коммит, уровень проверок, результат каждого
   набора, что получило `SKIP` и почему.

## Честность результата

- `SKIP` не приравнивается к успеху. «Модульные тесты пропущены, потому что
  YAxUnit не установлен» — это часть результата, а не деталь реализации.
- Отсутствие тестов на уровне не означает, что уровень пройден.
- Упавший тест не переинтерпретируется как «известная нестабильность» без
  записи в `docs/quality/DEFECTS.md`.
