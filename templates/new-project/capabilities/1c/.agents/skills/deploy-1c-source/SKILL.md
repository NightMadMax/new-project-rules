# Загрузка исходников в базу

Направление операции называется словами до её начала: **из репозитория в базу**.
Обратное направление — это `export-1c-source`, и путать их дорого.

## Исполнителя нет

Скрипта или MCP-вызова, выполняющего загрузку, capability не поставляет:
операция выполняется человеком по шагам ниже. Skill описывает порядок и гейты,
а не автоматизирует их — принимать его за работающую команду не нужно.

## Предусловия

1. Действующий session lock от `select-1c-project`, и фактическая база за
   портом подтверждена реальным вызовом. Порт закреплён в реестре, а база за
   ним меняется: «загрузка ушла не в ту базу» — та же угроза, что и для чтения.
2. Контур не production. База с `is_production = true` для этой операции не
   выбирается.
3. Подтверждённая свежая резервная копия базы: загрузка перестраивает
   конфигурацию, и откат возможен только из неё.
4. Названы ветка и коммит, которые разворачиваются. «Текущее состояние рабочего
   дерева» — не описание: незакоммиченные изменения указываются явно.
5. Для `source_format = edt` — XML-выгрузка через `export-1c-source`, включая
   его гейт XML-маршрута из scoped `configurations/AGENTS.md`: этот skill по
   определению идёт через конвертацию. Для `designer-xml` дерево берётся
   напрямую.

## После загрузки

- Проверить, что конфигурация базы соответствует развёрнутому коммиту.
- Обновление конфигурации базы проверяется до старта и после него. Само
  обновление — необратимая перестройка структуры данных: отдельное
  подтверждение, а не часть загрузки.
- Сообщить, что именно развёрнуто: база, контур, ветка, коммит.
