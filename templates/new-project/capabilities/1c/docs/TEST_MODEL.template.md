# Модель тестирования 1С

Уровни проверок и то, чем каждый выполняется. Уровень без исполнителя не
считается покрытием.

| Уровень | Чем выполняется | Когда |
|---|---|---|
| Синтаксис | `1c_syntax_check` и BSL Language Server | на каждое изменение BSL |
| Smoke | запуск конфигурации на выбранном non-prod | перед передачей изменений |
| Модульные | YAxUnit | на изменения бизнес-логики |
| Regression | YAxUnit + сравнение с baseline | перед обновлением базы |
| Performance | `measure-1c-performance` | по отдельной задаче |

## Модульные тесты

Тесты живут в расширении для тестов и хранятся в репозитории вместе с
конфигурацией. Прогон делает `deploy-and-test-1c`: разворачивает выбранный
non-prod, запускает YAxUnit и возвращает отчёт. На production он не работает
без отдельного разрешения.

YAxUnit — conditional-компонент: без него доступны только синтаксис и smoke,
и это состояние должно быть видно в отчёте, а не выглядеть как «тесты прошли».

## Чего здесь нет

UI и сценарные тесты (Vanessa Automation) в первую версию не входят. Ключ
`UI_TESTING` в `.dev.env` остаётся настройкой upstream и своего исполнителя не
имеет — задачу «прогнать UI-тесты» выполнить нечем.
