# Журнал изменений

Старые релизы перенесены в [[CHANGELOG_ARCHIVE|архив журнала изменений]].

## Unreleased

### Исправлено

- Ревью стандарта и соседней базы Best Practices четырьмя независимыми
  проходами — [[docs/reviews/REVIEW_2026-08-03_AUDIT|отчёт]]. Все гейты обоих
  репозиториев при этом были зелёными. Закрыто восемнадцать дефектов, №258–275.
  Барьеры сессии 1С сравнивали ячейку реестра с литералом нижнего регистра, а
  табличный редактор пишет `True` и `Managed`: `approved-write` выдавался на
  production-базу, а managed-база пропускала требование свидетельства о
  переключателе записи. Транзакция доставки не проверяла перед применением ни
  `adopt`, ни документы проекта — правка `INDEX.md` между планом и apply
  терялась молча. `reflect-and-record` отправлял кросс-проектные уроки в
  maintainer-only скилл, предусловиям которого свежий урок не удовлетворяет
  никогда: за месяц с 368 коммитами база не получила ни одного кандидата.
  Остальное по классам: локальная кодировка при чтении вывода git (69 мест,
  продолжение №231), кавычки csv в шестнадцати TSV-читателях, префикс ссылки, при
  котором `DEFECTS_ARCHIVE` скрывал `DEFECTS` и от установщика, и от валидатора,
  потеря концов строк и символов при правке индексов и журналов, BOM в реестре
  диагностики, печать значений вопреки заявлению отчёта, `--json` с traceback
  вместо плана.
- Классы закрыты инвариантами, а не местами: `scripts/test-*.py` обязан
  запускаться всеми тремя списками CI, `text=True` без явной кодировки
  запрещён по всему дереву, пользовательский скилл не может отправить читателя
  в maintainer-only ворота. Джоба `shell` закреплена на заявленном минимуме
  Python 3.9 — до этого CI брал версию runner'а и порог не проверялся.

- Закрыты решения о границах, №277–280, и №276 закрыт как `Won't Fix`. Runtime
  capability больше не может быть другой версией стандарта, чем та, что проект
  установил: `one_c_release_guard` сверяет `release_id`, и там, где пишут, это
  отказ, а не отметка в отчёте. Ядро capability читается из
  `config/capability-core.tsv` — литералы удалены, тест требует не совпадения
  двух копий, а одного источника. Валидация 1С вынесена в
  `scripts/one_c_validation.py`, ядро вызывает её через `CAPABILITY_VALIDATORS`,
  и тест запрещает `validate-project.py` называть артефакты одной capability.
  Вендоринг upstream сохранён намеренно: он даёт запиненные байты и офлайновый
  bootstrap, а вместо переноса добавлен `NOTICE.md` с источником, коммитом и
  разрешением автора, чей коммит тест сверяет с пином inventory.

### Изменено

- Best Practices: генератор кандидатов больше не падает на десяти из
  семнадцати стеков (таблица подписей теперь одна с валидатором), матрица
  переходов статусов из ADR-0005 стала исполняемой через `--history-base`,
  просроченная по `review_by` практика помечается при доставке, свежесть
  проверяется по расписанию, а пин стандарта получил сторожа, симметричного
  `bp-pin-watch`. Сам пин обновлён: он отставал на 284 коммита и запускал
  версию аудита до фикса №225. Набор вырос с 64 до 82 тестов.

## v1.17.0 — 2026-08-03

### Добавлено

- Ревью всего NPR пятью независимыми агентами (архитектура, Python, shell/CI,
  поставка, скиллы и документация) — [[docs/reviews/REVIEW_2026-08-01_NPR|отчёт]].
  Все автоматические гейты при этом были зелёными: найденное лежало вне зоны
  действующих проверок. Пять блокирующих находок закрыты, №205–№209.
  Capability с разделом документации поднимает профиль до `software` — иначе
  `minimal` + capability записывал все файлы, падал на индексации и откатом
  удалял каталог. Provider manifest больше не может дописать секцию в
  `.codex/config.toml`: проверялся `health`, а регистрировался `url`, и кавычка
  с переводом строки открывали таблицу с произвольной командой; теперь адрес
  проверяется как вход, `health` обязан принадлежать тому же серверу, а писатель
  TOML отказывается от значения, которое не может закавычить. Одиннадцать
  заполняемых документов `jira-confluence` переведены в `seed` — первая правка
  пользователя останавливала обновление всей capability вместе со скиллами.
  Ключи `.dev.env`, которые читает диагностика, наконец доставляются: раньше
  наш образец не был объявлен ни одной строкой манифеста, а тест называл его
  «shipped». Обязательная CI-джоба `cross-repo-e2e` получила `shell: bash` —
  на Windows она возвращала код только последней команды и покраснеть не могла.

- Настройка среды 1С получила исполнителей, и №173 закрыт: семь критериев
  готовности (10, 11, 12, 15, 17, 19, 20) перестали проверяться текстом skill.
  Каталог компонентов стал данными (`config/1c-components.tsv`), поэтому prompt
  собирается из обязательных полей — назначение, включаемые функции, класс,
  последствия отказа, версия, источник, требования admin/restart/сети/учётных
  данных и три варианта ответа; строка без любого из них не загружается.
  `scripts/one_c_setup.py` запускает только команду каталога и только по
  записанному ответу, перепроверяет результат тем же детектором и не пишет
  внутрь проекта, поэтому отказ установки не повреждает готовый репозиторий.
  `scripts/one_c_provider.py` обнаруживает внешний Docker deployment, проверяет
  identity, health и объявленные инструменты и отказывает на `docker run`,
  `compose` и `start`: второй комплект контейнеров отвечает на тех же портах и
  выглядит рабочим. `doctor-1c` возвращает версии EDT и EDT-MCP, состояние
  условных патчей и профили запуска, требуя плагин и профиль только для
  `application_kind=ordinary`. `approved-write` невозможен без названной
  резервной копии и не берётся на production ни при каком подтверждении.
  Совместимость: session lock, снятый предыдущей версией, запись больше не
  авторизует — его нужно снять заново, назвав проверенную копию.
  Следом закрыты №200–№204 из отложенных находок ревью: таблица каталога в
  подплане среды генерируется из TSV и сверяется точным сравнением, а не
  поиском слова; в каталоге появилась колонка `prerequisites` и поле «Требуется
  заранее» в prompt (Docker на чистой Windows называл `missing` без слова о
  WSL); диагностика берёт ключи `.dev.env` из каталога, а не из копии в коде;
  команды каталога используют плейсхолдер `{python}` вместо литерального
  `python3`; Docker Desktop перестал быть Windows-компонентом.
- Закрыты №175, №179, №180 и №186, и половин в матрице готовности не осталось.
